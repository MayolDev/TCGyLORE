## 2025-04-21 - Memory vs Database Grouping Performance
**Learning:** For statistics calculations (like cards by rarity), using Eloquent's `get()->groupBy()->map()->count()` loads every single model instance into memory (O(N) operation), which can cause severe memory and performance bottlenecks on large datasets. Even if the relationships are eager-loaded via `with()`, it's inefficient.
**Action:** When grouping and counting records, always push the calculation to the database using `select('foreign_id', DB::raw('count(*) as count'))->groupBy('foreign_id')`. For fetching the related names, use `with('relation:id,name')` to get just the needed fields, transforming it to an O(R) memory operation where R is the number of distinct related records (e.g., rarities) instead of total records. Ensure to handle relation access safely (e.g. `relationLoaded` / `getRelation`) if the model has a column shadowing the relation name.

## 2026-02-15 - N+1 Query due to Column/Relationship Name Conflict
**Learning:** In Laravel, if a model has a column (e.g., `rarity`) with the same name as a relationship method (`rarity()`), `$model->rarity` will return the column value (string) instead of the relationship instance. This causes `with('rarity')` to appear to fail (returns null or string access error) when accessed as a property, leading developers to think eager loading is broken or data is missing.
**Action:** When optimizing, always check for name collisions. Use `select()` to exclude the conflicting column if the relationship is needed, or rename the relationship. In this case, `Card::select(...)->with(...)` was used to exclude the `rarity` string column, allowing the relationship to be loaded and accessed correctly.

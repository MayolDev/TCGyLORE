## 2026-03-13 - O(N) memory to O(R) memory optimization in Dashboard Controller
**Learning:** The dashboard calculates the distribution of cards by rarity. Previously, it loaded all cards into memory using `Card::with('rarity')->whereNotNull('rarity_id')->get()` and then grouped them using a PHP collection method `groupBy()`. When dealing with thousands of cards, this operation causes severe memory overhead and O(N) model hydration cost where N is the total number of cards.
**Action:** When calculating statistics across a large number of records, use Eloquent's SQL aggregation methods (`select('rarity_id', DB::raw('count(*) as count'))->groupBy('rarity_id')`) instead of pulling all rows into memory and using Collection methods. This transforms an O(N) memory operation into an O(R) operation where R is the number of distinct categories (rarities). To preserve the null-relation fallback logic gracefully, maintain the `with('rarity')` constraint and handle the mapping logic over the returned aggregated collection.

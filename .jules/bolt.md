## 2026-03-12 - Optimize Card Rarity Distribution in Dashboard
**Learning:** Found an O(N) memory pattern in `DashboardController::index` where the entire `cards` table was fetched using `Card::with('rarity')->get()` just to count rarities. We optimized this using SQL `select('rarity_id', DB::raw('count(*) as count'))->groupBy('rarity_id')` to transform it into O(R) memory complexity (R = number of rarities). Also discovered that accessing `$card->rarity` shadows the relationship due to the column `rarity` (string enum legacy), so we must use `relationLoaded('rarity') && getRelation('rarity')` when iterating PHP collections to prevent string conflicts.
**Action:** When calculating grouped aggregates over large collections, always offload the counting to the database layer (`groupBy` + `DB::raw('count(*)')`). Be wary of column/relationship naming conflicts (like `Card::rarity`) and defensively use `relationLoaded` when safe accessing related data is required.

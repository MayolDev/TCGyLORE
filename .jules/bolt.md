## 2025-02-28 - Optimize N+1 memory operations and Relationship Shadowing in Collections
**Learning:** Large collections loaded via `Card::with('rarity')->get()` to perform grouping/counting in PHP can cause severe O(N) memory scaling bottlenecks. Furthermore, the `Card` model has a specific anti-pattern: an attribute naming conflict where `$card->rarity` can unexpectedly return the string column value instead of the eager-loaded relationship model.
**Action:** Always push grouping and counting logic to the database layer (e.g., using `select(DB::raw('count(*)'))->groupBy()`) to transform O(N) memory operations into O(R). To safely navigate the attribute shadowing conflict when iterating collections, use `$item->relationLoaded('rarity') && $item->getRelation('rarity')` rather than the magical `$item->rarity` property accessor. Additionally, optimize large payload queries (like `recent_cards`) by restricting eager-loaded relationships to only fetch essential columns (e.g., `with(['world:id,name'])`).

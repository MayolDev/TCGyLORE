
## 2026-03-08 - Optimize Dashboard rarity grouping to avoid N+1 and memory overhead
**Learning:** In the DashboardController, the card grouping by rarity was done in PHP memory (`->get()->groupBy(...)`) on all cards. With large amounts of cards, this causes a huge memory overhead and is quite slow due to eloquent hydrating thousands of models just to count them. It should be replaced with an optimized DB level query (`->select(...DB::raw...)->groupBy(...)`), dropping runtime memory overhead massively and getting rid of N+1 relationships when formatting the results. Also found that `Card` model has a column named `rarity` that shadows the relation `rarity()`, so the string version is returned by default, the workaround is `$card->relationLoaded('rarity') ? $card->getRelation('rarity') : null`.
**Action:** When grouping/counting things on relationships over a potentially large unpaginated set of rows, always prefer using Database aggregate queries over retrieving collections and processing them via PHP/Collections.
